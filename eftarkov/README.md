# EFTarkov 物价天梯增强

适用于 [EFTarkov 新版物价天梯](https://www.eftarkov.com/ranking) 的 Tampermonkey 脚本，支持 PvE、PvP 和 PvP Season（原站显示为“赛季”），并保留旧版 `news/web_210.html` 页面支持。

## 安装

脚本发布到仓库的 `main` 分支后，可打开 [GitHub Raw 安装链接](https://raw.githubusercontent.com/richardlzs/TampermonkeyScripts/main/eftarkov/eft-price.user.js)，在 Tampermonkey 中安装。首次安装前须确保该文件已经提交并推送到 `main`，否则链接不可用。

也可以在 Tampermonkey 中新建脚本，将 [`eft-price.user.js`](./eft-price.user.js) 的内容粘贴进去并保存，然后刷新天梯页面。脚本使用 `@grant none`，无需额外跨域权限。

脚本的 `@updateURL` 和 `@downloadURL` 都指向上述 Raw 文件。发布新版本时递增 `@version` 并将脚本推送到 `main`，Tampermonkey 才能检测并下载更新。

## 新版排行（/ranking）

- 名称搜索匹配完整名称或简称中包含的关键词，忽略大小写和首尾空格；留空表示不限。采用文本包含匹配，不提供错别字纠正或正则表达式。
- 跳蚤报价数量范围包含最小值和最大值，一端留空表示不限制该端，均留空表示不限。仅接受非负整数；输入非法或最小值大于最大值时，提示错误并保留最后一次有效范围。
- 名称与数量条件须同时满足，作用于当前模式、当前分类已经加载的物品。顶部显示筛选后的数量，各价格档显示“筛选后数量 / 本档总数”以及空结果提示。
- 沿用网站自己的分类和模式按钮。每种模式的名称、数量条件分别保存；切换分类保留同一模式的条件。“重置名称和数量”清除这两项条件，保留原站当前分类。
- 新版设置独立保存在 `eftarkov-ranking-filter-pve/pvp/season`。首次使用新版时继承旧设置的名称、数量条件，忽略旧分类限制；保存或重置新版条件不会覆盖旧版设置。

### 数据与范围

新版直接读取原站 `.ranking-item` 卡片中的完整名称、简称，以及 `.ranking-tooltip-source` 悬浮详情中的“报价数量”。支持整数和规范的千位分隔格式；缺失或非法数量视为未知，启用数量范围后排除这些物品，真实的 `0` 仍可匹配包含 `0` 的范围。

筛选范围仅限当前页面已经展示的数据，不额外请求其他分类、逐件查询物品接口或新增低价档位。新版展示的是原站“单价”排行，旧版的单格价值计算不用于新版。脚本不启动旧版 `boss.php` 请求，也不修改旧版 `localStorage.currentMode`。

## 旧版天梯（news/web_210.html）

- 沿用原站“跳蚤价格与最高商人收购价取较高值，再除以格子数”的算法。
- 在原站的 50,000 ₽/格以上五档之后增加 40,000、30,000、20,000、10,000 ₽/格起始的四档；50,000 ₽/格及以上物品仍由原站渲染。
- 从当前模式 API 的 `handbookCategories` 动态生成官方顶级和下级分类，筛选覆盖原站和新增的所有档位。
- 顶级和下级分类都可多选。一个已选顶级分类没有勾选下级分类时，显示该顶级分类的全部物品。“全部分类”取消分类限制，“清空分类”不显示任何物品；这两个按钮保留名称和数量条件。
- 名称搜索匹配完整名称或简称中包含的关键词，忽略大小写和首尾空格；留空表示不限。采用文本包含匹配，不提供错别字纠正或正则表达式。
- 跳蚤报价数量按 `最小值 ≤ lastOfferCount ≤ 最大值` 筛选，包含两端。一端留空表示不限制该端，均留空表示不限制数量。仅接受非负整数；输入无效或最小值大于最大值时提示错误并保留最后一次有效范围。
- 分类、名称和数量条件须同时满足，统一作用于全部九档。“重置所有筛选”恢复全部分类、空名称和不限数量。
- 原站会在本机浏览器的 `localStorage.currentMode` 中记住上次选择的模式；脚本不会覆盖已有值。当前页面以本页发起的模式请求为准，其他标签页切换模式后，本页刷新时才会跟随。每种模式的分类、名称和数量条件分别保存在 `localStorage`，切换模式并刷新后会恢复；已有旧版分类设置仍可读取。

### 数据与限制

脚本优先读取原站对 `boss.php?id=9/10/16` 的 `fetch` 响应；未捕获到时用页面原生 `fetch` 请求当前模式的数据。请求失败时，原站已有天梯仍可使用，新增档位及分类会显示错误状态。分类缺失的物品列在“未分类（接口无分类）”。

报价数量使用 API 的 `lastOfferCount`，不从页面已格式化的文本取值。数量缺失或非法时显示“未知”，启用数量范围后会排除这些物品；真实的 `0` 仍可匹配包含 `0` 的范围。

原站首次访问且尚未保存模式时，右下角显示“赛季”，价格页却默认请求 PvP。脚本在页面脚本运行前将首次模式设为 `season`，使原站和新增档位使用同一模式；已有的 `currentMode` 不会被改写。

此脚本是独立增强脚本，不是 EFTarkov 官方提供的脚本。无需也不应把原站 JavaScript 或完整 API 响应复制到本仓库。

## 开发验证

使用 Node.js 运行 `node eftarkov/eft-price.test.cjs`，检查新旧版入口隔离、模式解析、报价文本读取、名称与数量筛选、设置兼容，以及旧版响应乱序、价格下限和 HTML 安全。

3.2.0 已在内置浏览器的真实新版页面临时运行脚本，验证名称/简称匹配、数量边界、非法范围、分类导航、PvE/PvP/Season 条件隔离和重置。仍需在用户的 Tampermonkey 中安装更新，确认实际扩展加载与自动更新。
